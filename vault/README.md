# TradingBrain Obsidian Vault

Point Obsidian at this directory (`vault/`) as a vault. This is the
**knowledge layer** — long-term memory: research, theses, trade journals,
and reviews. It does not store bulk historical time-series data; that lives
in PostgreSQL (see [../docs/database.md](../docs/database.md)).

## Setup

1. Open Obsidian → "Open folder as vault" → select this `vault/` directory.
2. Install and enable the **Local REST API** community plugin
   (coddingtonbear/obsidian-local-rest-api). It exposes the HTTPS endpoint
   TradingBrain's `ObsidianKnowledgeStore` talks to.
3. Copy the plugin's API key into `OBSIDIAN_API_KEY` in your `.env`, and set
   `OBSIDIAN_BASE_URL` (default `https://127.0.0.1:27124`) and
   `OBSIDIAN_VAULT_PATH` (absolute path to this folder) to match.
4. Verify the integration: `python -m scripts.test_obsidian`.

Note templates live in [`_templates/`](_templates/) — enable either the
core **Templates** plugin or the community **Templater** plugin and point
it at that folder to use them when creating new notes by hand. TradingBrain
itself creates notes programmatically via `ObsidianKnowledgeStore`, using
the same structure as these templates.

## Folder structure

| Folder | Purpose |
|---|---|
| `00 Dashboard/` | Single entry-point note linking into the vault (watchlists, open theses, recent trades). Hand-maintained or regenerated by TradingBrain. |
| `01 Market/Daily/` | One note per trading day — market snapshot, macro, events, regime, hypotheses. See `_templates/Daily Market Note.md`. |
| `01 Market/Regimes/` | Notes describing observed market-regime periods and transitions (descriptive, not predictive — see Critical Design Rules). |
| `01 Market/Events/` | Notable market-moving events (macro prints, central bank decisions, index rebalances). |
| `02 Companies/India/`, `02 Companies/Global/` | One note per company. See `_templates/Company.md`. Split by market since coverage/valuation conventions differ. |
| `03 Sectors/` | Sector-level notes: dynamics, leaders/laggards, rotation observations. |
| `04 Macro/` | Macro themes and indicators (rates, inflation, currency, liquidity). |
| `05 Themes/` | Cross-cutting investment themes that span sectors/companies. |
| `06 Investment Theses/` | One note per thesis. See `_templates/Investment Thesis.md`. Linked from the company/theme it concerns. Changes must be auditable — see Rule 9. |
| `07 Trading/Trades/` | One note per trade. See `_templates/Trade.md`. |
| `07 Trading/Strategies/` | Strategy definitions/rules referenced by trades. |
| `07 Trading/Setups/` | Reusable technical/fundamental setup definitions. |
| `08 Research/` | Research Agent output (Phase 8) and manual research notes. |
| `09 Reviews/` | Trade-journal and thesis review output (Phase 10). |
| `10 Concepts/` | Reference notes on concepts, definitions, and mental models — the vault's glossary. |
| `11 Reports/` | Periodic (weekly/monthly) generated summary reports. |
| `99 Archive/` | Retired/closed notes moved out of active folders, kept for audit history. |

## Conventions

- Every note that represents a typed entity (company, thesis, trade, daily
  market note) uses YAML frontmatter matching its template's `type:` and
  required properties — this is what makes the notes queryable via
  `KnowledgeStore.search` / Dataview.
- Never let an automated write silently overwrite a human edit to `Thesis
  Statement`, `Bull/Base/Bear Case`, or `Invalidation Conditions` — thesis
  changes are appended as a new dated entry under `Historical Changes`
  (Rule 9).
- This is a **template vault** shipped with the repo. `.gitkeep` files mark
  otherwise-empty folders; real notes you create locally are yours — see
  `.gitignore` if you don't want personal notes tracked in this repo.
